## 一、技术选型

| 用途 | 选什么 | 为什么 |
| :--- | :--- | :--- |
| Python 环境 | **Python 3.12 + uv** | uv 一条命令装好 Python 和依赖，不污染系统 |
| Modbus 通讯 | **pymodbus 3.x** | Python 生态里最成熟的 Modbus 库，同时支持串口和 TCP |
| 串口枚举 | **pyserial**（pymodbus 自带依赖） | `list_ports.comports()` 是列 COM 口的标准做法 |
| 后端服务 | **FastAPI + uvicorn** | 自带 WebSocket，写控制接口几行就够；自带交互式文档 |
| 配置文件 | **PyYAML** | 串口、地址、轮询间隔这些不该写死在代码里 |
| 测试 | **pytest** | 配合本地模拟器，无硬件也能跑自动化测试 |
| 前端 | **原生 HTML + JS** | 需求是「简单的网页」，引框架反而累赘；不依赖 CDN，断网可用 |

**版本约束**：`pymodbus>=3.7,<4.0`。
3.x 内部 API 在版本之间改过几次（`slave=` 改成了 `device_id=`，部分方法签名也动过），**所以提示词里要求先做一次冒烟测试确认 API**，别照着网上老文章写。

## 二、⭐ 提示词：搭环境 + 立骨架

> **用法**：打开 WorkBuddy，**切到「允许完全访问」**，新建任务，把下面整段复制进去。
> 提示词**没有写死路径**——它会自动把「当前工作目录下的 `sensor-hub`」当作项目根目录，并在开工前先确认、开头先报告实际使用的绝对路径。

````text
# 任务：为「RS485 传感器监控平台」搭建 Python 开发环境和项目骨架

## 你的角色
你是一名 Python 后端工程师。请一步一步实际执行并验证，不要假设成功。
遇到报错自行诊断修复。最后输出一份结构化自检报告。

## 背景
要做一个 RS485 传感器监控平台：用 pymodbus 读取三个传感器，并提供一个网页做实时展示和控制。
本次只做「环境 + 目录骨架 + 依赖」，不写任何业务逻辑。

## 目标环境
- 系统：Windows 10/11
- Shell：PowerShell
- Python 版本：3.12（用 uv 管理）
- 依赖管理：uv（不是 pip，不是 poetry）

## 目标位置（不要写死路径）
项目根目录 = **当前工作目录下的 `sensor-hub` 子目录**。
开工前先执行 `Get-Location` 确认当前工作目录；如果我在这段对话里另外指定了路径，以我指定的为准。
**不要使用任何写死的盘符或用户名路径**（别人的机器和你不一样）。
在你输出的**第一行**，先报告你实际使用的绝对路径。

## 执行步骤

### 第 1 步：检查前置条件
1. 输出系统版本和 PowerShell 版本。
2. 运行 `uv --version`；如果未安装，用 `winget install --id=astral-sh.uv -e` 安装，
   装完必须重开终端再验证。仍失败则用
   `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`。
3. 运行 `uv python list --only-installed` 确认有 3.12.x；没有就 `uv python install 3.12`。

### 第 2 步：创建项目并初始化
1. 创建项目目录（当前工作目录下的 `sensor-hub`）并进入，然后打印它的绝对路径确认。
2. 运行 `uv init --python 3.12 --name sensor-hub`。
3. 删除 uv 自动生成的示例 main.py 和 hello.py（如果存在）。

### 第 3 步：安装依赖
用 uv 添加以下依赖，并记录实际装到的版本号：
uv add "pymodbus>=3.7,<4.0" pyserial pyyaml "fastapi>=0.110" "uvicorn[standard]"
uv add --dev pytest pytest-asyncio

### 第 4 步：确认 pymodbus 的实际 API（重要，别跳过）
不同小版本的 pymodbus 3.x 参数名不一样，必须实测确认。运行下面的命令并把输出贴出来：
uv run python -c "import pymodbus, inspect; print('version:', pymodbus.__version__); from pymodbus.client import ModbusSerialClient, ModbusTcpClient; print('serial read sig:', inspect.signature(ModbusSerialClient.read_holding_registers)); print('tcp read sig:', inspect.signature(ModbusTcpClient.read_holding_registers)); print('serial init:', inspect.signature(ModbusSerialClient.__init__))"
根据输出，明确指出：
- 读寄存器时从机地址参数叫什么（device_id / slave / unit）
- 构造客户端时波特率、校验位等参数名
把这个结论写进项目 README.md 的「开发备注」一节。

### 第 5 步：创建目录骨架
创建以下文件（暂不实现逻辑，只放模块 docstring 和 `TODO`）：
app/__init__.py
app/modbus_base.py      # 统一 Modbus 客户端基类：支持 serial 和 tcp 两种传输
app/devices.py          # 三个传感器的驱动类
app/hub.py              # 采集调度与缓存
app/simulator.py        # 本地 Modbus 从机模拟器
app/server.py           # FastAPI 后端
static/index.html       # 前端单页
tools/scan_ports.py     # 枚举串口
tools/scan_slaves.py    # 扫描从机地址
tools/regtool.py        # 通用寄存器读写
tools/debug_light.py        # 光照度调试脚本
tools/debug_ultrasonic.py   # 超声波调试脚本
tools/debug_alarm.py        # 声光报警器调试脚本
tests/test_devices.py   # 单元测试
run.py                  # 一键启动入口
docs/                   # 空目录，后面放协议摘要（protocol.md）
每个 .py 文件都要有模块级 docstring 说明职责，函数体先留 `raise NotImplementedError` 或 `pass`。

### 第 6 步：配置 VSCode，让用户「点一下就能跑」
**这一步很重要。** 用户不想每次都敲命令，要能在 VSCode 里点右上角的 ▶ 直接运行。

1) 创建 `.vscode/settings.json`：
{
  "python.defaultInterpreterPath": "${workspaceFolder}\\.venv\\Scripts\\python.exe",
  "python.terminal.activateEnvironment": true
}

2) 创建 `.vscode/launch.json`，配好下面 8 个启动项。**每个都必须能不带任何参数直接跑**：
   · 启动监控服务         → run.py
   · 启动本地模拟器       → 模块方式跑 app.simulator
   · 调试光照度           → tools/debug_light.py
   · 调试超声波           → tools/debug_ultrasonic.py
   · 调试报警器（只读）   → tools/debug_alarm.py（不带 --yes，dry-run）
   · 扫描串口             → tools/scan_ports.py，args 为 ["--only-usb"]
   · 扫描从机地址         → tools/scan_slaves.py
   · 跑全部测试           → pytest

   每个配置都要包含：name、type 为 "debugpy"、request 为 "launch"、
   console 为 "integratedTerminal"、justMyCode 为 true、cwd 为 "${workspaceFolder}"。
   脚本用 "program": "${workspaceFolder}/tools/xxx.py"；
   模块用 "module": "app.simulator"；
   pytest 用 "module": "pytest"（配 "args": ["-v"]）。

   注意：这 8 个入口对应的脚本会在后续步骤里逐步实现，
   **在本步骤之前它们还只是空壳，跑起来会报 NotImplementedError —— 这属正常**。
   你的任务是保证配置本身正确、JSON 合法。

3) 创建 `.vscode/extensions.json`：
{ "recommendations": ["ms-python.python", "ms-python.vscode-pylance", "charliermarsh.ruff"] }

4) 在项目 README.md 里写一节「怎么运行」，按这个顺序讲：
   ① 首选：打开 .py 文件 → 点编辑器右上角 ▶（或 Ctrl+F5）
   ② 带参数的入口：点 ▶ 右边的小三角 ▾ → 选配好的启动项
   ③ 备选：命令行（列出等价命令，这节要保留）

### 第 7 步：写配置文件 config.yaml
内容如下：

```yaml
transport: simulator          # serial | simulator（simulator = 连接本地模拟器）
poll_interval: 1.0            # 采集间隔（秒）

serial:                       # 串口参数：全局默认，单台设备可在 devices 下覆盖
  port: COM3
  baudrate: 9600
  parity: N
  stopbits: 1
  bytesize: 8
  timeout: 1.0

simulator:
  host: 127.0.0.1
  port: 5020

devices:                      # 三台设备的通讯参数
  light:                      # 光照度变送器
    enabled: true
    slave_id: null            # 待填：从接口文档读取后填写
    baudrate: null            # 待填
  ultrasonic:                 # 超声波测距模组
    enabled: true
    slave_id: null            # 待填
    baudrate: null            # 待填
  alarm:                      # 声光报警器
    enabled: true
    slave_id: null            # 待填
    baudrate: null            # 待填
```

**⚠️ 关于 `slave_id` / `baudrate` 为什么留 `null`：**
这三台设备的**出厂从机地址和波特率必须以厂商接口文档为准**，本步骤**不要凭印象或经验填数字**，
也**不要上网搜**。下一步（第 2 篇）会让你**读取厂商接口文档**，把正确的值填进来。
现在保持 `null` 即可——`config.yaml` 能正常解析就算通过。

### 第 8 步：自我验证
依次运行并把输出贴出来：
1. uv run python -c "import pymodbus, serial, yaml, fastapi, uvicorn; print('deps OK')"
2. uv run python -c "import yaml,pathlib; d=yaml.safe_load(pathlib.Path('config.yaml').read_text(encoding='utf-8')); print(d['transport'], list(d['devices'].keys()), d['devices']['light']['baudrate'])"
3. uv run python -c "import json,pathlib; a=json.loads(pathlib.Path('.vscode/launch.json').read_text(encoding='utf-8')); print('launch 配置数:', len(a['configurations'])); [print(' -', c['name']) for c in a['configurations']]"
4. uv run pytest -q
5. uv tree

### 第 9 步：输出自检报告
用表格汇报：
| 检查项 | 结果 |
| uv 版本 | |
| Python 版本 | |
| pymodbus 版本 | |
| 从机地址参数名（实测） | |
| 依赖是否全部可导入 | |
| config.yaml 是否可解析 | |
| .vscode/launch.json 是否合法 | |
| launch.json 里有几个启动项 | |
| pytest 是否可运行 | |
| 已创建的目录树 | |
最后补一段「本步骤踩到的坑及解决办法」。

## 约束
- 用 uv 管理一切，不要用 pip install（除 uv 自身的安装）。
- 不要写入任何 Modbus 业务逻辑，本步骤只搭骨架。
- **全部从零实现**：不要复制粘贴任何既有脚本，也不要让项目 import 它们。
- **不要凭记忆或上网搜索去填设备参数**。三台设备的从机地址、波特率在 `config.yaml` 里一律先留
  `null`，它们的正确值要等**读取厂商接口文档**之后才能确定（下一步会做）。
  本步骤只保证配置文件结构正确、能被解析。
- **所有可运行入口都必须「不带参数也能跑」**：默认值一律从 `config.yaml` 读取，
  命令行参数只作临时覆盖。这样才能在 VSCode 里点 ▶ 直接运行。
- 每个入口都要在 `.vscode/launch.json` 里配一个启动项，并在项目 README 里给出等价命令。
- 不要在代码或配置里写死盘符、用户名或本机串口号。
- 每一步都要贴出真实命令和真实输出，禁止编造。
- 某一步失败就停下来汇报原因和可选方案，不要跳过继续。
````

## 六、常见问题

**Q1：`uv` 提示找不到命令？**
安装完必须**关闭并重开终端**。仍不行则把 `%USERPROFILE%\.local\bin` 加进用户 PATH。

**Q2：装依赖特别慢？**
换国内源：
```powershell
[Environment]::SetEnvironmentVariable("UV_DEFAULT_INDEX","https://pypi.tuna.tsinghua.edu.cn/simple","User")
```
改完重开终端。

**Q3：为什么不用 pip + requirements.txt？**
能用，但 uv 更快、能锁版本、还能顺带管理 Python 本身。换电脑只要 `uv sync`。

**Q4：为什么骨架文件名是 `devices.py` 而不是每个传感器一个文件？**
三个驱动加起来不到 300 行，放一个文件更好读。等设备超过 5 个再拆包。

**Q5：不做第 4 步（实测 API）行不行？**
强烈不建议。pymodbus 3.x 的从机地址参数在 `slave` / `device_id` / `unit` 之间改过，猜错的话后面每个调用都会报 `TypeError`。
